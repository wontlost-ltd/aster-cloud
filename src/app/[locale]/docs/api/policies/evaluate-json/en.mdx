# Evaluate Core IR JSON Policy

Evaluate a policy expressed as a Core IR JSON document directly, without CNL parsing or compilation. Use this endpoint when your application compiles policies itself (for example in the browser with `@aster-cloud/aster-lang-ts`) and sends the compiled representation to the engine.

## Endpoint

`POST /api/v1/policies/evaluate-json`

## Required Role

`MEMBER`

## Headers

| Header | Value | Required |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Yes |
| `Content-Type` | `application/json` | Yes |
| `X-Tenant-ID` | Tenant identifier string | Yes |

## Request Body

```json
{
  "policy": "string (Core IR v2 JSON)",
  "context": {}
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `policy` | `string` | Yes | A JSON-encoded string containing a **Core IR v2** module (`"schemaVersion": 2`). Submit the `coreJson` string returned by `compile()` from `@aster-cloud/aster-lang-ts` 2.x unchanged. The engine reads it strictly against the Core IR v2 schema and executes it, bypassing all CNL parsing steps. |
| `context` | `object` | Yes | A single object whose keys map to the declared parameter names of the entry-point function in the Core IR. |

### Core IR JSON Format

The `policy` string must be a Core IR v2 document as defined by the Core IR v2 JSON Schema: the top-level object has `"schemaVersion": 2` (a JSON integer), `"kind": "Module"`, `name`, `profile`, `origin` and `decls`. Every field is always present — absent scalars and objects are `null`, absent lists are `[]` — and unknown fields are rejected. Do not write this JSON by hand: compile the CNL source and send `coreJson` as-is.

The example below is the exact `coreJson` that `compile()` produces for this source:

```text
Module Discount.

Define Order has total as Int.

Rule calculate given order as Order, produce Int:
  If order.total greater than 100
    Return 10.
  Otherwise
    Return 0.
```

When embedding this as the `policy` field in the request, the IR must be a JSON string (i.e. the entire document becomes a string value).

## Response Body

```json
{
  "result": "<any>",
  "executionTimeMs": 0,
  "error": null,
  "evidence": { "correlationId": "<uuid>" }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `result` | `any` | The value returned by the entry-point function in the Core IR. |
| `executionTimeMs` | `number` | Wall-clock time in milliseconds from IR deserialization to response dispatch. |
| `error` | `string \| null` | Error message; `null` on success. |
| `code` | `string` | Machine-readable error code; only present on failure (see the status table). |
| `field` | `string` | Path of the missing input field; only present with `code: "missing_input_field"`. |
| `evidence` | `object` | Evidence reference for this evaluation; `correlationId` links the response to the audit chain. |

Policies whose entry rule returns a `Verdict` additionally return `decision`, and `ruleId` / `controls` when the rule carries `@id` / `@control` annotations.

## HTTP Status Codes

| Status | Meaning |
|--------|---------|
| `200 OK` | Evaluation succeeded. |
| `400 Bad Request` | `code: "unsupported_schema_version"` — `policy` is not Core IR v2 (missing `schemaVersion`, or not the integer `2`). `code: "invalid_request"` — the Core IR fails schema or invariant checks (for example an unknown or missing field), the `agent` block is invalid, or `context` cannot be mapped to the entry function parameters. `code: "function_not_executable"` — the function selected as entry point cannot be executed directly (the message says which function to call). `code: "missing_input_field"` — `context` lacks a field the rule reads (`field` names the path). `code: "input_too_deep"`, `"input_cyclic"`, `"input_invalid_key"` or `"input_unsupported_value"` — the shape of `context` is not supported. |
| `401 Unauthorized` | Missing or invalid bearer token. |
| `403 Forbidden` | Token is valid but the caller lacks the `MEMBER` role, or the plan does not include the Policy Execution API (`error: "api_access_denied"`, body with `error` / `message` only). |
| `404 Not Found` | `code: "function_not_found"` — the Core IR has no function to execute. |
| `422 Unprocessable Entity` | `code: "execution_timeout"` — the evaluation exceeded the wall-clock limit. `code: "output_too_deep"`, `"output_cyclic"` or `"output_invalid_key"` — the result cannot be returned as JSON. |
| `429 Too Many Requests` | `error: "rate_limit_exceeded"` — the per-key requests-per-second limit was exceeded; retry after the `Retry-After` header (body: `error`, `message`, `rps_limit`, `rps_used`). `error: "api_quota_hard_exceeded"` — the monthly API quota hard limit was exceeded; there is no `Retry-After` and retrying does not help until the quota resets or the plan changes (body: `error`, `message`, `limit`, `used`). Neither body has the evaluation response fields. |
| `500 Internal Server Error` | `code: "evaluation_failed"` — the policy failed at run time (no internal details are returned). |

```js [JavaScript]
import { compile } from '@aster-cloud/aster-lang-ts/browser';

// Compile the CNL source in your application
const compiled = compile("Module Discount.\n\nDefine Order has total as Int.\n\nRule calculate given order as Order, produce Int:\n  If order.total greater than 100\n    Return 10.\n  Otherwise\n    Return 0.\n");
if (!compiled.success) throw new Error(JSON.stringify(compiled.parseErrors));

const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/policies/evaluate-json',
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer <token>',
      'Content-Type': 'application/json',
      'X-Tenant-ID': 'acme-corp',
    },
    body: JSON.stringify({
      // Core IR v2, canonical bytes — send unchanged
      // The Core IR is sent as a string
      policy: compiled.coreJson,
      context: {
        order: { total: 150 },
      },
    }),
  }
);

const data = await response.json();
// data.result → 10
```

```json
  "result": 10,
```

```json
{
  "result": null,
  "executionTimeMs": 3,
  "error": "Core IR JSON 解析失败: Core IR 不符合 v2 契约：[CoreIrProblem[path=/schemaVersion, code=unsupported_schema_version]]",
```
