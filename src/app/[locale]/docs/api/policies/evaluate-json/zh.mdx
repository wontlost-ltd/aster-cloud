# 评估 Core IR JSON 策略

直接评估以 Core IR JSON 文档表达的策略，无需 CNL 解析或编译。当你的应用自行编译策略（例如在浏览器中使用 `@aster-cloud/aster-lang-ts`）并向引擎发送编译结果时，使用此端点。

## 端点

`POST /api/v1/policies/evaluate-json`

## 必需角色

`MEMBER`

## 请求头

| 请求头 | 值 | 必需 |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | 是 |
| `Content-Type` | `application/json` | 是 |
| `X-Tenant-ID` | 租户标识符字符串 | 是 |

## 请求体

```json
{
  "policy": "string (Core IR v2 JSON)",
  "context": {}
}
```

| 字段 | 类型 | 必需 | 描述 |
|-------|------|----------|-------------|
| `policy` | `string` | 是 | 包含 **Core IR v2** 模块（`"schemaVersion": 2`）的 JSON 编码字符串。直接提交 `@aster-cloud/aster-lang-ts` 2.x 的 `compile()` 返回的 `coreJson` 字符串，不要改动。引擎按 Core IR v2 schema 严格读入后执行，跳过所有 CNL 解析步骤。 |
| `context` | `object` | 是 | 单个对象，其键映射到 Core IR 中入口函数声明的参数名。 |

### Core IR JSON 格式

`policy` 字符串必须是符合 Core IR v2 JSON Schema 的文档：顶层对象含 `"schemaVersion": 2`（JSON 整数）、`"kind": "Module"`、`name`、`profile`、`origin` 与 `decls`。所有字段恒输出——缺省的标量与对象为 `null`，缺省的列表为 `[]`——未知字段会被拒收。不要手写这份 JSON：编译 CNL 源码后原样发送 `coreJson`。

下例就是 `compile()` 对这段源码产出的 `coreJson`：

```text
Module Discount.

Define Order has total as Int.

Rule calculate given order as Order, produce Int:
  If order.total greater than 100
    Return 10.
  Otherwise
    Return 0.
```

将其作为请求中 `policy` 字段嵌入时，IR 必须是 JSON 字符串（即整个文档成为一个字符串值）。

## 响应体

```json
{
  "result": "<any>",
  "executionTimeMs": 0,
  "error": null,
  "evidence": { "correlationId": "<uuid>" }
}
```

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `result` | `any` | Core IR 中入口函数返回的值。 |
| `executionTimeMs` | `number` | 从 IR 反序列化到响应分发的挂钟时间（毫秒）。 |
| `error` | `string \| null` | 错误消息；成功时为 `null`。 |
| `code` | `string` | 机器可读的错误码；仅失败时出现（见状态码表）。 |
| `evidence` | `object` | 本次评估的证据引用；`correlationId` 把响应与审计链关联起来。 |

入口规则返回 `Verdict` 的策略还会返回 `decision`；规则带 `@id` / `@control` 注解时另返回 `ruleId` / `controls`。

## HTTP 状态码

| 状态 | 含义 |
|--------|---------|
| `200 OK` | 评估成功。 |
| `400 Bad Request` | `code: "unsupported_schema_version"`——`policy` 不是 Core IR v2（缺少 `schemaVersion`，或不是整数 `2`）。`code: "invalid_request"`——Core IR 未通过 schema 或不变式检查（例如有未知字段或缺字段），或 `context` 与入口函数参数不匹配。 |
| `401 Unauthorized` | 缺少或无效的 Bearer token。 |
| `403 Forbidden` | Token 有效但调用者缺少 `MEMBER` 角色。 |
| `404 Not Found` | `code: "function_not_found"`——Core IR 中没有可执行的函数。 |
| `500 Internal Server Error` | `code: "evaluation_failed"`——策略运行时失败（不返回内部细节）。 |

```js [JavaScript]
import { compile } from '@aster-cloud/aster-lang-ts/browser';

// 在你的应用中编译 CNL 源码
const compiled = compile("Module Discount.\n\nDefine Order has total as Int.\n\nRule calculate given order as Order, produce Int:\n  If order.total greater than 100\n    Return 10.\n  Otherwise\n    Return 0.\n");
if (!compiled.success) throw new Error(JSON.stringify(compiled.parseErrors));

const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/policies/evaluate-json',
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer <token>',
      'Content-Type': 'application/json',
      'X-Tenant-ID': 'acme-corp',
    },
    body: JSON.stringify({
      // Core IR v2 规范字节——原样发送
      // Core IR 以字符串形式发送
      policy: compiled.coreJson,
      context: {
        order: { total: 150 },
      },
    }),
  }
);

const data = await response.json();
// data.result → 10
```


```json

  "result": null,
  "executionTimeMs": 3,
  "error": "Core IR JSON 解析失败: Core IR 不符合 v2 契约：[CoreIrProblem[path=/schemaVersion, code=unsupported_schema_version]]",
  "code": "unsupported_schema_version"
}
```
