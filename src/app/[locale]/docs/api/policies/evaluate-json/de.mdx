# Core-IR-JSON-Policy evaluieren

Evaluieren Sie eine Policy direkt als Core-IR-JSON-Dokument, ohne CNL-Parsen oder Kompilierung. Nutzen Sie diesen Endpunkt, wenn Ihre Anwendung Policies selbst kompiliert (zum Beispiel im Browser mit `@aster-cloud/aster-lang-ts`) und das Kompilat an die Engine sendet.

## Endpunkt

`POST /api/v1/policies/evaluate-json`

## Erforderliche Rolle

`MEMBER`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `Content-Type` | `application/json` | Ja |
| `X-Tenant-ID` | Mandanten-Kennung als String | Ja |

## Request-Body

```json
{
  "policy": "string (Core IR v2 JSON)",
  "context": {}
}
```

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `policy` | `string` | Ja | Ein JSON-kodierter String mit einem **Core-IR-v2**-Modul (`"schemaVersion": 2`). Senden Sie den von `compile()` aus `@aster-cloud/aster-lang-ts` 2.x gelieferten `coreJson`-String unverändert. Die Engine liest ihn strikt gegen das Core-IR-v2-Schema ein und führt ihn aus, ohne CNL zu parsen. |
| `context` | `object` | Ja | Ein einzelnes Objekt, dessen Schlüssel den deklarierten Parameternamen der Einstiegsfunktion in der Core IR entsprechen. |

### Core-IR-JSON-Format

Der `policy`-String muss ein Core-IR-v2-Dokument gemäß dem Core-IR-v2-JSON-Schema sein: Das Wurzelobjekt enthält `"schemaVersion": 2` (eine JSON-Ganzzahl), `"kind": "Module"`, `name`, `profile`, `origin` und `decls`. Alle Felder sind immer vorhanden – fehlende Skalare und Objekte sind `null`, fehlende Listen `[]` –, unbekannte Felder werden abgelehnt. Schreiben Sie dieses JSON nicht von Hand: Kompilieren Sie den CNL-Quelltext und senden Sie `coreJson` unverändert.

Das folgende Beispiel ist genau das `coreJson`, das `compile()` für diesen Quelltext erzeugt:

```text
Module Discount.

Define Order has total as Int.

Rule calculate given order as Order, produce Int:
  If order.total greater than 100
    Return 10.
  Otherwise
    Return 0.
```

Beim Einbetten als `policy`-Feld im Request muss die IR ein JSON-String sein (das gesamte Dokument wird zu einem String-Wert).

## Response-Body

```json
{
  "result": "<any>",
  "executionTimeMs": 0,
  "error": null,
  "evidence": { "correlationId": "<uuid>" }
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `result` | `any` | Der von der Einstiegsfunktion in der Core IR zurückgegebene Wert. |
| `executionTimeMs` | `number` | Wanduhrzeit in Millisekunden von der IR-Deserialisierung bis zum Versand der Antwort. |
| `error` | `string \| null` | Fehlermeldung; `null` bei Erfolg. |
| `code` | `string` | Maschinenlesbarer Fehlercode; nur bei Fehlern vorhanden (siehe Statustabelle). |
| `field` | `string` | Pfad des fehlenden Eingabefelds; nur bei `code: "missing_input_field"` vorhanden. |
| `evidence` | `object \| absent` | Evidenzreferenz dieser Evaluierung; `correlationId` verknüpft die Antwort mit der Audit-Kette. Nur vorhanden, wenn die Evaluierung ausgeführt und protokolliert wurde (bei Erfolg und bei Fehlern während der Ausführung); fehlt, wenn die Anfrage vor der Ausführung abgelehnt wird, etwa mit `unsupported_schema_version`, `invalid_request` oder `function_not_found`. |

Policies, deren Einstiegsregel ein `Verdict` liefert, geben zusätzlich `decision` zurück, und `ruleId` / `controls`, wenn die Regel `@id`- / `@control`-Annotationen trägt.

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Evaluierung erfolgreich. |
| `400 Bad Request` | `code: "unsupported_schema_version"` – `policy` ist keine Core IR v2 (`schemaVersion` fehlt oder ist nicht die Ganzzahl `2`). `code: "invalid_request"` – die Core IR besteht die Schema- oder Invariantenprüfung nicht (etwa ein unbekanntes oder fehlendes Feld), der `agent`-Block ist ungültig, oder `context` lässt sich nicht auf die Parameter der Einstiegsfunktion abbilden. `code: "function_not_executable"` – die als Einstieg gewählte Funktion kann nicht direkt ausgeführt werden (die Meldung nennt die aufzurufende Funktion). `code: "missing_input_field"` – `context` fehlt ein Feld, das die Regel liest (`field` nennt den Pfad). `code: "input_too_deep"`, `"input_cyclic"`, `"input_invalid_key"` oder `"input_unsupported_value"` – die Form von `context` wird nicht unterstützt. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `MEMBER`-Rolle, oder der Tarif enthält die Policy Execution API nicht (`error: "api_access_denied"`, Body nur mit `error` / `message`). |
| `404 Not Found` | `code: "function_not_found"` – die Core IR enthält keine ausführbare Funktion. |
| `422 Unprocessable Entity` | `code: "execution_timeout"` – die Evaluierung hat das Zeitlimit überschritten. `code: "output_too_deep"`, `"output_cyclic"` oder `"output_invalid_key"` – das Ergebnis lässt sich nicht als JSON zurückgeben. |
| `429 Too Many Requests` | `error: "rate_limit_exceeded"` – das Limit an Anfragen pro Sekunde für den Schlüssel ist überschritten; nach dem `Retry-After`-Header erneut versuchen (Body: `error`, `message`, `rps_limit`, `rps_used`). `error: "api_quota_hard_exceeded"` – das harte monatliche API-Kontingent ist überschritten; ohne `Retry-After`, ein erneuter Versuch hilft erst nach dem Zurücksetzen des Kontingents oder einem Tarifwechsel (Body: `error`, `message`, `limit`, `used`). Beide Bodies enthalten keine Evaluierungsfelder. |
| `500 Internal Server Error` | `code: "evaluation_failed"` – die Policy ist zur Laufzeit fehlgeschlagen (ohne interne Details). |
| `503 Service Unavailable` | `error: "plan_check_unavailable"` – die Tarifprüfung ist vorübergehend nicht verfügbar; nach dem `Retry-After`-Header erneut versuchen (Body: `error`, `message`). |

```js [JavaScript]
import { compile } from '@aster-cloud/aster-lang-ts/browser';

// CNL-Quelltext in Ihrer Anwendung kompilieren
const compiled = compile("Module Discount.\n\nDefine Order has total as Int.\n\nRule calculate given order as Order, produce Int:\n  If order.total greater than 100\n    Return 10.\n  Otherwise\n    Return 0.\n");
if (!compiled.success) throw new Error(JSON.stringify(compiled.parseErrors));

const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/policies/evaluate-json',
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer <token>',
      'Content-Type': 'application/json',
      'X-Tenant-ID': 'acme-corp',
    },
    body: JSON.stringify({
      // Core IR v2, kanonische Bytes – unverändert senden
      // Die Core IR wird als String gesendet
      policy: compiled.coreJson,
      context: {
        order: { total: 150 },
      },
    }),
  }
);

const data = await response.json();
// data.result → 10
```

```json
  "result": 10,
```

```json

  "result": null,
```
