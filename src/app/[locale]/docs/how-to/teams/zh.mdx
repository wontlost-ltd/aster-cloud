# 邀请团队成员并分配业务角色

团队是共享的工作区。团队策略、团队 API 密钥和审批都属于团队而不是某一个人，审阅人和审批人因此可以在同一套规则上协作。

## 创建团队

1. 打开[团队](/teams)，点击「新建团队」。
2. 填写团队名称和团队 URL（小写字母、数字和单个连字符），点击「创建团队」。

你会成为团队所有者。创建团队需要包含团队功能的套餐，团队的成员上限由所有者的套餐决定。已经加入的团队在任何套餐下都能查看，也都能接受邀请。

## 邀请成员

1. 打开团队，进入**成员**页。
2. 在「邀请新成员」中填写对方的邮箱并选择角色，点击「发送邀请」。
3. 邀请 7 天内有效。被接受之前，它列在「待处理邀请」中，你可以随时撤销。

被邀请人用该邮箱对应的账号登录后，会在仪表盘和团队页看到这条邀请并接受。

<Callout type="tip" title="接受邀请需要同一个邮箱">
邀请只能由收件邮箱对应的账号接受。用其他邮箱登录的人会被提示切换账号。
</Callout>

## 团队角色

每位成员有一个团队角色，决定其在团队中能做什么：

| 角色 | 可以做什么 |
|---|---|
| 所有者 | 全部操作，包括删除团队和转让所有权。每个团队只有一位所有者。 |
| 管理员 | 管理成员和邀请、修改团队设置，创建、编辑、删除和审批团队策略。 |
| 成员 | 查看团队，创建、编辑和运行团队策略。 |
| 查看者 | 查看团队及其策略。 |

管理员不能邀请或提升任何人到与自己相同或更高的角色，也不能修改其他管理员。

## 业务角色

业务角色是一个标签，例如 `Credit Officer` 或 `Data Protection Officer`，与团队角色相互独立。策略规则可以要求由特定业务角色作出决定，例如 `Verdict.require_approval("Credit Officer", "large_exposure")`。只有恰好持有该业务角色的成员才能批准或驳回这类请求，详见[审批](/docs/how-to/approvals)。

分配业务角色：

1. 打开团队的**成员**页。
2. 在某位成员的「业务角色」旁点击「编辑」。
3. 输入角色，用逗号分隔，点击「保存」。

每个角色为 1 到 64 个可打印 ASCII 字符，不含逗号；每位成员最多 16 个。匹配是精确匹配，拼写要与策略中一致。

谁能修改业务角色：

- 所有者可以修改任何人的，包括自己的；
- 管理员可以修改成员和查看者的，但不能修改自己的、所有者的或其他管理员的。

<Callout type="warning" title="业务角色即审批权限">
给某人分配业务角色，就是让其可以决定要求该角色的审批。请审慎分配审批人角色，人员调岗时及时移除。
</Callout>
