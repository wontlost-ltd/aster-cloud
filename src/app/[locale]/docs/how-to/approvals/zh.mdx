# 审批全流程

[审批](/approvals)页汇集了所有等待人工决定的事项，范围覆盖你的个人工作区和你所在的每个团队。这里有两类请求：

- **策略版本审批**：有人请求批准某个已保存的策略版本，批准后它才会被执行。
- **动作审批**：经 Aster Guard 接入的策略判定某个 AI Agent 的动作需要人工批准后才能执行。

## 策略版本审批

策略每保存一次就生成一个新版本，新版本初始为草稿。

1. 打开策略，进入**版本**（「版本与审批」页）。
2. 在草稿或已驳回的版本旁选择「提交审批」，可以附上发布说明。
3. 该版本进入待审批状态，出现在审批页的「策略版本审批」中，也会出现在每位有权审批者的仪表盘上。
4. 审批人打开该版本，批准或驳回。每个决定都记录在该版本的审批历史中。

谁可以审批一个版本：

- **个人策略**：你自己（所有者）。可以批准自己的提交。
- **团队策略**：**作者以外**的团队所有者或管理员。这就是四眼原则：作者能看到请求，但不能作决定。如果团队里除作者外没有其他所有者或管理员，就没有人能审批；收件箱会提示这一点，并链接到团队设置，方便你任命管理员。

执行使用哪个版本：设置了默认版本时用默认版本；否则用已批准的最高版本；从未有版本获批时，用最近一次保存的内容。

## 动作审批

动作审批来自 [Aster Guard](/docs/how-to/guard)。AI Agent 提出一个动作（例如删除客户记录），这个动作在执行前先交给你的策略裁决。规则返回 `Verdict.require_approval("<业务角色>", "<原因>")` 时，动作会等待人工决定。

1. 请求出现在「动作审批」中，列出策略、动作、**所需角色**和工作区。
2. 展开「查看决策输入」，看策略当时看到了什么。被遮盖的字段保持遮盖，除非你持有所需角色并选择显示原值；显示原值会以你的名义记入审计链。
3. 批准，或填写原因后驳回。Agent 的调用随之继续或被拦下。

谁可以决定动作审批：

- 只有**已验证业务角色**与所需角色完全一致的成员。业务角色在团队成员页按成员设置，见[邀请团队成员并分配业务角色](/docs/how-to/teams)；其他人看到的是「仅查看」。规则以升级方式（`Verdict.escalate(...)`）提交、未指定角色时，任何成员都可以决定；
- 发起该动作的一方永远不能自己审批，必须由其他人决定。

无人及时处理的请求会过期。请求所依赖的签名输入的事实签发方被吊销时，请求也会自动过期。

<Callout type="tip" title="按状态分页查看">
动作审批按状态分为待审批、已批准、已驳回和已过期。已决定的请求会显示决定人。
</Callout>

## 在哪里找到待办

- **仪表盘**：「等待你审批的策略版本」列出你现在就能审批的版本。
- **审批**：两类请求都在这里，包括你只能查看的。
- **通知**：有需要你的角色处理的新动作审批时，会收到站内通知。
