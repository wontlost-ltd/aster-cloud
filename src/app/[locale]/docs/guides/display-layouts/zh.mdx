# 短策略的显示排版（LayoutMap）

**显示排版**（LayoutMap）是策略版本源码的第二种排列，专门给人读：例如把一首诗按诗行排出来，或者把短规则里的关键词换成日常用语。**canonical 源码**仍是唯一被编译和执行的内容。显示排版从不执行：执行、证据、Cedar 与策略包导出、What-If 和 Guard 只读 canonical 源码，排版也不属于版本的源码信封（envelope）或哈希。

显示排版只用于展示性文本和小型策略。编写排版需要[结构化编写](/docs/guides/structured-authoring-admin)；查看排版只需要该策略的读权限。

## 排版的构成

排版是一串片段（span），按顺序拼起来必须与 canonical 源码逐字相同：

- **内容片段**是源码中的一段，原样显示；
- **结构片段**是源码中的一段（它的 *canonical* 文字），加上显示在原处的文字（它的 *display*）。display 可以为空，即隐藏这一段。

JSON 形式（格式版本 1）：

```json
{"v":1,"spans":[{"text":"Module pricing.\n\nRule discountedPrice given amount as Float, tier as Text, produce Float:\n  "},{"canonical":"If","display":"When"},{"text":" tier equals to \"gold\":\n    "},{"canonical":"Return","display":"Charge"},{"text":" amount * 0.8.\n  "},{"canonical":"Return","display":"Charge"},{"text":" amount."}]}
```

它对应的源码：

```
Module pricing.

Rule discountedPrice given amount as Float, tier as Text, produce Float:
  If tier equals to "gold":
    Return amount * 0.8.
  Return amount.
```

显示出来是 "When tier equals to "gold": Charge amount * 0.8."。名称、数字和文本值都在内容片段里，所以在显示排版中与源码完全一致。

## 防止误导性排版的规则

每次保存都会按版本的源码、语言和关键词别名检查排版。第一条不满足的规则会拒绝保存：

| 错误码 | 规则 |
|---|---|
| `layout_invalid_format` | JSON 不是合法排版：除 `v`、`spans` 外还有别的键（片段除 `text`，或 `canonical` 与 `display` 外还有别的键）、版本不是 1、没有片段、内容片段为空、结构片段的 canonical 为空，或片段边界落在一个字符中间。 |
| `layout_too_large` | 超出某项规模上限（见下文），响应会指出是哪一项。 |
| `layout_roundtrip_mismatch` | 片段拼起来与源码不完全相同，响应给出第一个不同之处的偏移。 |
| `layout_structural_hides_value` | 结构片段覆盖了关键词、标点、空白和注释以外的内容：名称、数字、文本值，或 `true`、`false` 等字面量词。会影响判定结果的值和名称只能放在内容片段里，而内容片段总是原样显示。 |
| `layout_content_parity` | 排版没有可见的内容片段，或某个结构片段含有引号。 |
| `structured_authoring_required`（HTTP 403） | 你提交了排版，但在这条策略上没有结构化编写能力。 |

以上面的示例为例：把 `0.8` 标为结构片段并显示为 "20% off"，会报 `layout_structural_hides_value`——读者将看不到规则实际使用的数字。

## 规模上限

| 上限 | 最大值 |
|---|---|
| 源码大小 | 12,288 字节（UTF-8） |
| 源码行数 | 200 |
| 片段数（相邻的内容片段算一个） | 400 |
| 保存的排版 | 49,152 字节 |
| 全部显示文字 | 24,576 字节 |
| 单个结构片段的显示文字 | 256 个字符 |

源码超出上限时，排版标签页会说明是哪一项超限，并且不提供排版。

## 在编辑器中创建排版

有结构化编写能力时，编辑器侧栏有一个**排版**标签页。

1. 点击**开始排版**。排版从一个内容片段开始，即源码原样显示。（也可以点击**导入 JSON** 粘贴一份排版。）
2. 在编辑器中选中关键词、标点或空白，点击**将选区标为结构**。选区必须完全落在同一个内容片段内。
3. 在**结构片段**下为每个片段填写显示文字，留空即隐藏。**恢复为内容**把片段变回源码文字。
4. 打开**并排视图**，宽屏下显示排版出现在编辑器左侧。选区在两边同步高亮，问题标在显示排版上，点击显示排版会把光标移到编辑器中的对应位置。
5. 标签页在你编辑时检查排版，显示**排版有效。**，或给出第一处问题并提供**跳到第 *n* 行**。
6. 保存策略，排版随新版本一起保存。

显示排版会标出只存在于排版中的每一段文字：结构片段的文字使用独立样式，悬停时显示对应的 canonical 文字，被隐藏的关键词会留下一个标记。

## 版本与保存

排版属于某一个版本，保存后不再改动。

- **只改排版也会建新版本。**再次保存完全相同的排版则不会。
- 点击**移除排版**后保存：新版本不带排版。
- **修改源码后**，拼不回新源码的排版即失效。标签页会提示*源码已改动，此排版已失效*；排版不会自动重新对齐。点击**从恒等排版重新开始**重来，或点击**移除排版**。
- **保存时没有动排版**：如果当前排版对新的源码、语言和别名仍满足全部规则，并且你有结构化编写能力，新版本沿用它；否则新版本不带排版。编辑器能在保存前判断出这种情况时，会请你确认（*此版本将不再带显示排版*）。只要保存时丢弃了排版，编辑器都会提示新版本没有排版。之前的版本仍保留各自的排版。

最后这条规则意味着：没有结构化编写能力的队友仍可以编辑并保存带排版的团队策略。保存不会被拒绝，只是新版本不带排版。

已保存的排版如果与版本不再对应（例如直接改过数据库），它不会显示，也不会加载到编辑器；读者看到的是 canonical 源码和一条提示。

## 评审者与审批者看到什么

canonical 源码总是排在第一位：

- **策略页面与版本详情**（审批者在这里评审版本）：默认打开 **Canonical 源码（参与执行）** 标签；**显示排版（不参与执行）** 是第二个标签，并注明编译、执行、评审与审批都使用 canonical 源码。
- **版本对比**只比较 canonical 源码。排版不同时，另起一行显示**显示排版已变更**。
- **复核面板**：策略带排版时，会有一条说明指出排版不参与执行，并链接到版本列表。

词汇字面量术语改变的是源码的含义，而不是排版。要查看它们代表的文本值，请使用[词汇规范预览](/docs/guides/domain-vocabulary#词汇规范预览)。

## 通过 API

`POST /api/v1/policies/{id}/versions`（以及编辑器自身的保存请求）接受 `layout` 字段：

| `layout` | 新版本 |
|---|---|
| 省略 | 按上面的规则沿用当前排版 |
| `null` | 不带排版 |
| 排版对象 | 使用这份排版，前提是你有结构化编写能力且它满足全部规则 |

失败时返回 `{ "error", "code", "offset"?, "limit"? }`，`code` 为上表中的某个错误码。保存成功时，如果当前版本有排版而新版本没有沿用，响应带 `layoutDropped: true`。读取版本（`GET /api/v1/policies/{id}/versions/{version}`）返回 `layout`，其 `status` 为 `none`、`ok`（附排版）或 `inconsistent`。

## 尚未提供

决策轨迹（decision trace）按 canonical 源码显示，暂不映射到显示排版上，因为轨迹还不带源码位置。
