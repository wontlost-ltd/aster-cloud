# 守卫、审批与执行日志

Aster Cloud 是编写、审批和部署守卫（Guard）策略的地方，也是由人审阅 Agent 所申请动作的地方。本页介绍控制台做了什么。Agent 一侧——决策 API、签名执行收据、consume 与对账，以及 `@aster-cloud/aster-guard` SDK 与 MCP 代理——见 [aster-lang.dev 上的 Action Guard](https://aster-lang.dev/zh/docs/action-guard)。

## 把策略部署到守卫

Agent 按模块与函数指定策略，例如 `guard.customer/decide`。守卫评估的版本就是该策略在 Aster Cloud 中的**默认版本**。

- **设为默认版本时先部署。** 只有策略 API 接受了部署，控制台才提交新的默认版本。策略 API 不可达时，你会得到一个可重试的错误，默认版本保持不变。极少数情况下控制台在部署与提交之间出错，下面的后台核对会让两者重新一致。
- **并发修改。** 如果别人同时修改同一策略的默认版本，较慢的那次请求会被拒绝，需要重新操作。
- **回收站与恢复。** 把策略移入回收站会把它从守卫撤回；恢复后重新部署。从未部署过的策略，即使策略 API 不可用也可以删除。
- **收敛。** 后台任务每 5 分钟核对一次：已部署到守卫的每条策略是否仍在运行其当前默认版本，并补完没有完成的部署或撤回。

守卫评估已部署的版本时，使用的源码、关键词别名、语言与冻结的领域词汇和 Aster Cloud 编译时完全相同，入口规则也与控制台执行所用的相同。

## Agent 拿到什么

对 `ALLOW`，守卫返回一份签名的执行收据。Agent 必须先验签、再 consume（只能一次），然后才执行。签名覆盖租户、动作哈希以及策略模块与函数，所以从另一条更宽松的策略拿到的 `ALLOW` 不能挪用。请使用 `@aster-cloud/aster-guard` 0.3.0 或更高版本（已发布到 npm）：它按固定顺序完成验签、consume 与结果回写，没有跳过它们的选项。

从 Aster Cloud 发起的执行也在其中。声明了 `eu-ai-act-high-risk` 档案的策略执行结果为 `ALLOW` 时，Cloud 同样为它登记守卫决策（与 `REQUIRE_APPROVAL`、`ESCALATE` 一样），因此输入来源检查覆盖每一种结论。

## 处理一条审批

待审批出现在**审批**页；策略版本的待审批也会出现在仪表盘上（见[编辑器与仪表盘](/zh/docs/guides/workspace#仪表盘)）。当你已验证的业务角色包含守卫审批所需的角色，或该项是升级（escalation）时，你可以处理它。你不能裁决自己申请的动作。

裁决之前先打开**查看决策输入**。面板展示规则据以裁决的输入，并做了打码：

| 你看到的 | 含义 |
|---|---|
| `L2 · email` 徽标 | 策略声明为 `@pii` 的字段，显示其级别与类别。 |
| *未声明类型，不可见* | 值与声明的类型不符，或嵌套过深。 |
| *未声明字段* | 一个对象里策略没有声明的全部键合并成的一项。键名同样隐藏，因为键名本身就可能是个人数据。 |
| 明文值 | 已声明且没有 `@pii` 的字段。文本仍会经过模式打码（邮箱地址、电话号码、卡号等）。 |

每个字段还标明它的值是**已验证**（由已登记的事实签发方签名）还是调用方**自报**。面板提示签名事实已过期时，这只是一条说明：事实在做出决策时核验，有效期 10 分钟。它们过期不影响你能否批准；如果签发方已被吊销，请求会被自动拒绝。

如果你持有所需角色且审批仍在等待中，**显示原值**会还原已声明的 `@pii` 值。每次还原都会以你的名义记入审计链，面板也会说明你是在打码视图上还是在已还原的原值上做裁决。未声明的内容任何人都不能还原，升级项也不能还原。

你的裁决绑定在你看到的视图上。打开之后输入视图如果变了，裁决会被拒绝，面板重新加载当前视图，你需要重新审阅。

## 执行日志

策略的**执行日志**页列出它的执行记录。在那里，没有人能看到 `@pii` 原值——执行策略的人看不到，owner 与 admin 也看不到。该页没有还原入口。

- **输入**按与审批面板相同的规则打码。标记来自实际运行的策略版本：声明为 `@pii` 的字段显示级别与类别，未声明的字段被合并并隐藏，其余文本经过模式打码。无法加载该版本的类型信息时，所有值都会隐藏。
- **输出**中的每个文本值都经过同一套模式打码，能识别邮箱地址、电话号码、卡号等模式；但**识别不了**由输入派生的自由文本：规则返回 `"Hello, " + applicant.name` 时，日志里会出现这个名字。*自 1.0.49 / `aster-lang-ts` 3.2.0 起提供：* 编译器会对这类规则报警告 `W709`（用 `@pii` 值拼出返回的 `Text`）。它只是警告，不阻止保存；见 aster-lang.dev 上的[个人数据作为文本返回](https://aster-lang.dev/zh/docs/governance#个人数据作为文本返回w709)。
- 你执行策略后立即看到的响应是你本次请求的结果，不经过这个视图打码。
- 打码只改变显示的内容。存储的输入与输出，以及回放、What-If 与证据包使用的哈希都不变。证据包不包含执行输入。
