# 结构化编写管理指南

**结构化编写**为策略编辑器提供编写辅助：[模型](/docs/guides/domain-modelling#模型标签页)、[词汇](/docs/guides/domain-vocabulary#词汇标签页)和[排版](/docs/guides/display-layouts#在编辑器中创建排版)标签页、词汇规范预览，以及命令面板里对应的命令。它也决定谁可以保存[显示排版](/docs/guides/display-layouts)。

它不限制语言本身。结构体、类型别名、导入别名和词汇术语，无论有没有结构化编写，任何人都可以编写、保存、编译和执行。

## 谁可以使用

只有以下条件全部满足时，一个人才能在某条策略上使用结构化编写，按此顺序检查：

1. **全局开关已开启。**默认关闭。
2. **套餐允许。**Free 以外的所有套餐都包含它：Trial、Pro、Enterprise，以及已下线的 Team 套餐。看的是这条策略的套餐：个人策略看作者本人的套餐，团队策略看团队 owner 的套餐。
3. **此人有授权**，来自以下至少一个来源：
   - 平台管理员给的**直接授权**；
   - 授予此人所在团队的**团队授权**，且此人在该团队的角色不是 viewer；
   - 此人所在团队的 owner 给的**委派**，且此人角色不是 viewer，同时该团队和全平台的委派都处于开启状态。

授权和套餐缺一不可：授权不能代替套餐，套餐也不能代替授权。团队授权或委派让此人在任何地方都获得这项能力，但套餐仍按每条策略判断。因此 Free 套餐的成员可以在 Pro 团队的策略上使用它，在自己的个人策略上则不能。

检查不通过时，编辑器与没有结构化编写时完全一样：没有这些标签页，也没有预览。

## 开启

1. 打开[管理后台](/admin)，在**平台控制**下的**功能开关**中找到**结构化编写**，点击**开启**。
2. **结构化编写：团队 owner 委派**默认开启。关闭后所有团队 owner 都不能委派；已有委派在重新开启前不生效。

开关的变更最多需要约一分钟才能在所有服务器上生效。关掉再打开开关不会改动任何授权：所有授权恢复原样。每次变更都以 `platform_setting.update` 记入审计日志。

## 授予用户和团队

打开**管理 → 结构化编写**（`/admin/capabilities/structured-authoring`）。

**用户标签**：按邮箱或姓名搜索。**来源**列列出此人获得能力的每个来源：`direct`、`team:<团队>` 或 `delegated:<团队>`。**授予**添加直接授权，**撤销**移除它。本页只撤销直接授权：团队授权在团队标签中撤销，委派由团队 owner 撤销。

**团队标签**：每个团队有：

- **团队授权**：把能力授予该团队除 viewer 以外的所有成员。
- **座位上限**（0 到 10,000）：团队 owner 最多可以委派给多少名成员。**owner 委派**：为该团队开启或关闭委派。点击**保存**同时生效。
- **已用座位**：仍在团队中的成员的有效委派数，包括之后被改为 viewer 的成员。

没有保存过座位上限的团队不能委派。座位上限低于已用座位时会被拒绝，请先撤销委派。座位的计数与分配在团队行锁内进行，因此同时发起的委派也不会超过上限。

## 团队 owner 委派座位

团队 owner 在团队设置中看到**结构化编写座位**（只有 owner 能看到，团队 admin 看不到）。owner 可以：

- 查看已用座位和座位上限；
- 选择一名成员并点击**委派**，viewer 不在可选范围内；
- 撤销一项委派以释放座位。

团队的委派被暂停或全平台关闭委派时，owner 不能新增委派，但仍可撤销。被改为 viewer 的成员保留座位，但在重新提升角色前失去能力。owner 看不到平台管理员直接授予成员的授权。

## 权限结束后会发生什么

| 事件 | 效果 |
|---|---|
| 撤销直接授权或团队授权 | 该来源从此人的下一次请求起不再计入。 |
| 撤销委派 | 同上，并释放座位。 |
| 成员离开或被移出团队 | 该团队的团队授权和委派立即对此人失效；委派被撤销，座位释放。 |
| 成员被改为 viewer | 团队授权和委派暂停，座位仍被占用；角色恢复后随即恢复。 |
| 团队被删除 | 撤销其团队授权和全部委派，并删除其座位上限。 |
| 转让团队所有权 | 委派保持不变，由新 owner 管理。 |
| 关闭委派（团队或全平台） | 委派暂停，不撤销；重新开启委派即恢复。 |
| 关闭全局开关，或套餐降级 | 在相关策略上任何人都不能使用这项能力。授权保留，开关或套餐恢复后重新生效。 |

无论哪种情况，已有内容都照常可用：

- 用到结构体、别名或词汇术语的策略仍然有效，可以编译和执行，也可以继续编辑和保存，只是没有编写辅助。
- 已保存的显示排版，任何能读这条策略的人都仍可查看。执行从不读取排版。
- 没有结构化编写能力的人为带排版的策略保存新版本时，保存成功，新版本不带排版。之前的版本仍保留各自的排版。

已经打开的编辑器在刷新页面前保留原来的标签页，但只要保存的内容包含或沿用排版，服务器就会重新检查这项能力。

## 审计记录

| 操作 | 何时记录 |
|---|---|
| `capability.grant` | 新建直接授权、团队授权或委派 |
| `capability.revoke` | 撤销授权；`reason` 说明原因，例如 `manual`、`member_removed` 或 `team_deleted` |
| `capability.allotment.update` | 团队的座位上限或 owner 委派变更，或团队被删除 |
| `platform_setting.update` | 结构化编写的开关变更 |
