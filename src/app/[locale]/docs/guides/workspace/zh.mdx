# 编辑器与仪表盘

本页介绍 Aster Cloud 策略编辑器与仪表盘最近的变化。

## 新建策略从模板开始

**新建策略**打开时预填一份简短的入门策略，语言跟随界面：中文界面用中文，德文界面用德文，其余情况用英文（目前还没有印地文入门模板，所以印地文界面也用英文）。策略的源码语言就是入门模板的语言，所以编辑器的词法、补全与保存时的语言都一致。

- 编辑器上方的提示条写明入门模板的语言，并提供**从空白开始**，也可以直接关闭提示。
- 未改动的入门模板不算草稿：不会自动保存，离开页面也不会弹确认。第一次改动——手工编辑、套用模板或由助手写入——之后它才成为你的草稿。
- 已保存的草稿仍然优先：和以前一样，会提示你恢复它。
- 入门模板也是编辑器**模板**页签中的第一条（**入门**分类下的**基础入门**），点了「从空白开始」之后还能把它找回来。
- 从文档打开某个示例的链接（`?template=…`）只显示该示例。
- 编辑器里还是未改动的入门模板时，助手的**生成**会从零写一条新策略，而不是改写入门模板。

## 语言服务器连接

编辑器里的诊断、补全等语言功能来自语言服务器。每次连接或重连之前，编辑器都向 Aster Cloud 申请一张短时票据：票据绑定你的用户，有效期 60 秒，只能使用一次。浏览器里不再下发任何共享凭据。

- 空闲 15 分钟的会话会被关闭，你继续操作时编辑器会重新连接。
- 每个用户同时最多保持三个语言服务器会话，再多的会话会被关闭。如果新开的编辑器标签页没有语言功能，请关掉不用的编辑器标签页。

## 导出为 Cedar

在策略详情页，**导出为 Cedar** 导出的是未指定版本时运行的那个版本——默认的已批准版本，否则为最新的已批准版本。草稿永远不会被导出。导出成功会下载 Cedar 策略文件与 schema 文件，并报告结果经过多少个探针验证。哪些内容可以导出、结论如何映射，见 [aster-lang.dev 上的导出到 Cedar](https://aster-lang.dev/zh/docs/cedar-export)。

## 仪表盘

仪表盘顶部的两张卡片汇集了以前容易漏掉的待办：

- **待处理邀请**——不必打开团队页就能接受或拒绝邀请。
- **等待你审批的策略版本**——至多五个版本，附总数与直达的**审批**链接。只列出你有权批准的版本；谁可以批准什么并没有改变，所以团队策略的作者仍需等待另一位审批人。

没有待办时两张卡片都不显示。在小屏幕上，通知面板不会超出屏幕，审批表格改为卡片列表，各表格的操作列也始终可见。

## 双引擎一致性

公开的[一致性页面](/equivalence)报告 TypeScript 引擎与 JVM 引擎是否一致。页面先给结论——全部检查一致，或有多少项不同——以及最近一次夜间检查的日期；报告超过 72 小时未更新会标为过期，没有数据时不显示任何数字。下面依次是比较的三项内容（解析、运行结果与 Core IR）、测试覆盖、标出历史分歧的夜间检查记录、尚未解决的分歧，以及方法说明与原始 CSV 数据链接。

## 无障碍

在浅色与深色主题下，文字、控件与代码高亮都达到 WCAG AA 对比度。在移动端，点击目标至少为 44 × 44 CSS 像素。文档里的代码块可以用键盘访问，复制后会给出提示，焦点在各处都清晰可见。
