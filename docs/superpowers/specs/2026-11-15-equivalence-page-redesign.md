# /equivalence 页面重设计（#764）

## 问题

现状（`src/app/[locale]/equivalence/page.tsx` + `parity-trend-chart.tsx`）：

1. **没有结论**。页面打开是一张 150 天 × 5 序列的分组柱状图，每根柱都顶到 100%，
   在桌面上读作「条形码」，在手机上是一块彩色噪点。访客要自己从 5 个
   `100.0%` 卡片里推断「两个引擎是否一致」。
2. **没有日期**。页面任何地方都不显示最近一次测量的时间；若 nightly 停跑，
   页面仍然显示 100%，不诚实。
3. **概念混在一起**。「一致率」（parse / eval / IR：两个引擎是否给出同一结果）与
   「覆盖率」（eval 覆盖 / 特性覆盖：测了多少）被做成五个一模一样的 chip，
   颜色也一样重要，读者无法区分「一致」和「测得够不够」。
4. **方法说明过时**。footer 仍写「暂不涵盖 Core IR 字段级一致」，但 IR 一致率
   早已每晚测量并显示在页面上。
5. **已解决分歧台账难读**。删除线 + 三列窄表，手机上每个单元格折成 4–5 行。
6. **没有站点框架**。无 logo、无语言切换、无返回首页入口；用的是裸 `gray-*`
   色而非设计 token，与 /solutions、/pricing 风格不一致。

## 读者

潜在用户和技术评估者（风控 / 合规 / 架构评审），他们要回答一个问题：
**「我能相信 Java 和 TypeScript 两个引擎对同一条规则给出同一个结果吗？证据新不新？」**

次要读者：已经信任、想看原始数据或方法的工程师。

## 信息层级（渐进披露）

1. **结论（Hero）**——一句话 + 日期：
   - 一致：「两个引擎在全部 1,593 项检查中结果一致」，下方
     「最近一次检查 2026年11月15日 · 每晚自动运行」。
   - 有分歧：「最新一次运行中有 N 项检查两个引擎结果不同」（danger 色）。
   - 过期：结论保留，但叠加 warning 提示「最新报告已 X 天未更新，夜间任务可能未运行」。
   - 无数据：EmptyState，链接到数据仓库。
   「检查数」= parse 样本 + eval 黄金用例 + IR 样本，即每晚实际比较两个引擎的次数。
2. **三个比较维度卡片**（一致率）：解析 / 运行结果 / Core IR。每张卡：
   通俗说明（这一层比较什么）、`一致数 / 总数`、状态徽章（一致 / 分歧 N）、
   相对上一次测量的回退提示（若下降）。
3. **测得够不够**（覆盖率，视觉降级为两条进度条）：可求值样本的黄金用例覆盖、
   语言特性的双引擎执行覆盖。下降时同样标注。
4. **历史**：把「柱高 = 百分比」改为「每晚检查数」折线（三条线，覆盖范围在增长），
   某天若有分歧则该点画成红色空心点。悬浮 / 聚焦显示当天三项的 `一致/总数`。
   保留时间范围切换与「显示数据表」（无障碍替代：表格包含三项每天的数值）。
5. **分歧**：
   - 当前有分歧 → danger 区块，按维度列出数量，链接到原始报告
     （`equivalence-report.json`、`DIVERGENT-MANIFEST.md`、`IR-DIVERGENCE-LEDGER.md`）。
   - 已解决分歧台账 → 改为卡片列表：用例名、「之前 TS 输出 / Java 输出」并排、修复说明。
6. **方法**：要点列表（更新为现状：五个 CSV、IR 已覆盖、02:00 UTC），原始数据链接、
   白皮书入口。

## 删除 / 合并

- 删除 5 个同质 chip → 拆为 3 张一致率卡 + 2 条覆盖率进度条。
- 删除「qualifier」段落（解析层说明）→ 并入每张卡的通俗说明。
- 删除 150 天分组柱状图 → 检查数折线图（同一组件文件重写，仍是手写 SVG，
  理由不变：严格 CSP + Workers 包体，不引第三方图表库）。
- 旧 footer 5 条 → 方法区要点（修正 IR 过时说法）。
- 白皮书 CTA 并入方法区。

## 状态判定（纯函数 `summarizeParity`，单测覆盖）

| 状态 | 判定 |
| --- | --- |
| `empty` | 三个一致率维度都没有数据 |
| `diverged` | 任一一致率维度最新一次 `value < total`（优先于 partial） |
| `partial` | 无分歧但有一致率维度缺数据 → 结论只称「已加载的 N 项检查一致」，警告列出缺失层 |
| `agree` | 三个一致率维度都有数据且最新 `value === total` |
| `stale`（叠加） | 最新测量时间距现在 > 72 小时（nightly 每天跑；容忍一次漏跑） |
| 维度 `regressed` | 该维度最新 rate 低于上一天（按 UTC 日去重后）的 rate |
| 维度 `missing` | 该维度 CSV 拉取失败或为空 → 卡片显示「暂无数据」，结论降为 `partial` |
| 维度测量日期落后 | 该维度最新测量与 `lastChecked`（只取一致率维度）不在同一 UTC 日 → 卡片标出自己的测量日期 |

各维度最新测量不保证来自同一次运行，故结论文案称「最新测量 / 最新结果」，不称「同一次运行」。
CSV 行若计数非整数、为负或分子大于分母，直接丢弃。

## 数据契约

不变：仍在服务端以 `revalidate: 3600` 拉取 aster-lang-test 的五个 history CSV，
不新增数据源。URL `/[locale]/equivalence` 不变，JSON-LD 保留（更新描述以包含 IR）。

## 响应式 / 暗色 / 无障碍

- 只用设计 token（`bg`/`fg`/`border`/`success`/`danger`/`warning`/`primary`）与
  `@/components/ui` 原语（Container、Card、Badge、Alert、EmptyState），暗色自动跟随
  `data-theme`；序列色同时有形状/标签区分，不单靠颜色。
- 卡片：手机单列，`sm` 起三列；历史图在窄屏保持 16:9 比例，x 轴只标首尾日期。
- 结论区为 `<h1>`，状态用文字表达（不只是颜色/图标）；图表 `role="img"` 带文字摘要，
  数据表作为替代；范围切换用 `aria-pressed` 按钮组；所有链接可键盘聚焦。
- 动效仅 `motion-safe`。
