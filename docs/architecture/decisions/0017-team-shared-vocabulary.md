# 0017 — 团队共享领域词汇（UserDomainTerm.ownerType='team'）

Status: Proposed
Date: 2026-11-06
Issues: #672
Companions: 0016（团队策略授权，本 ADR 取代其「后果」一节中「词汇额度后续由 #672 重新设计」的遗留项）、
0015 §5（团队资源的套餐门槛看 owner）、`aster-lang` ADR 0051（领域词汇按位置解析、§7 封印、§8 同作用域写法冲突）

## 背景

领域词汇是按作者存储的个人对象（`UserDomainTerm.ownerType='user'`，CHECK 约束要求 `teamId IS NULL`），额度只在
写词条时按**本人**套餐检查（`getLexiconQuota`）。团队里的 Free 成员因此不能为团队策略新增词条，即使团队 owner 是 Pro（#672）。

#690 曾把额度改为「本人与所在团队 owner 套餐取较大者」，审查 M3 否决：Free 账号的个人词汇与个人策略也会享受团队档，
一个 Pro owner 能给任意多个 Free 账号开出 Pro 额度，离队后多出的词条也收不回。裁决是**团队档只作用于团队场景**。
在现有数据模型下，这等于要有「团队拥有的词汇」。schema 自 0021 起就为此预留了 `ownerType` / `teamId` 两列。

## 决策

### 1. 数据：启用团队归属

- `UserDomainTerm` 允许两种归属：`ownerType='user' AND teamId IS NULL`（个人，原样）或
  `ownerType='team' AND teamId IS NOT NULL`（团队）。团队行的 `userId` 记**创建者**，只用于审计与「改自己创建的」判定，
  不代表归属。
- 活跃唯一约束按归属拆分：个人行 `(userId, termId)`，团队行 `(teamId, termId)`；另建团队行的 `(teamId, domain, locale)` 索引。
- 快照表 `UserVocabularySnapshot` 早已允许 `ownerType='team'`，团队词汇冻结写 `ownerType='team', ownerId=teamId`。
- 迁移 0065 只放宽约束、换索引，不改数据。

### 2. 可见词汇：团队词汇 + 作者个人词汇，冲突时团队优先

团队策略（`Policy.teamId` 非空）在编辑器、保存编译门禁（`loadSaveVocabulary`）、草稿执行 / 重编译
（`loadLiveVocabularyForPolicy`）、审批冻结（`freezeVocabularyForApproval`）四处读同一份词汇：
**团队词汇 ∪ 作者个人词汇**，作用域规则（同 CNL 语言、被源码引用）不变。个人策略只读作者个人词汇，与现状一致。

冲突口径沿用 ADR 0051 §8 的定义：同角色、同作用域（字段 / 枚举成员按父名），NFC 后写法完全相同却映射到不同规范名。

- 同一归属内的冲突仍在保存词条时拒绝（现有规则不变）。
- 跨归属（团队 vs 作者个人）的冲突在合并时裁决：**丢弃作者个人词条，保留团队词条**，并把被遮蔽的个人词条返回给编辑器，
  显示提示「团队词汇优先：你的个人词条 X 在团队策略中不生效」。仅大小写不同不算冲突，两者并存，使用点由引擎
  「精确优先、折叠唯一」判定（ADR 0051 现有规则）。完全相同的映射照常去重。

理由：团队词汇是团队成员共同维护的约定，个人词汇只是作者的习惯写法；不裁决的话，引擎会在使用点报歧义，
团队策略的可编译性就取决于「谁最后保存」，这正是共享词汇要消除的。只读团队词汇（不合并作者个人词汇）会让现有团队策略
在上线当天全部失去作者词汇而编译失败，属于破坏性变更，故不采用。

审批冻结时，团队词汇冻进团队快照，作者词汇（已剔除被遮蔽的条目）冻进作者快照；执行端合并全部引用快照的规则不变，
冻结时的一致性校验（与保存时封印的 `sourceScopesJson` 比对）按合并后的词汇做。

### 3. 角色与额度

| 动作 | owner | admin | member | viewer | 非成员 / 已离队 |
|------|-------|-------|--------|--------|------------------|
| 查看团队词汇 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 新增团队词条 | ✓ | ✓ | ✓ | ✗ | ✗ |
| 修改 / 删除 / 恢复他人创建的团队词条 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 修改 / 删除 / 恢复自己创建的团队词条 | ✓ | ✓ | ✓ | ✗ | ✗ |

- 角色每次请求按**当前**成员关系判定（`checkTeamAccess`，绕过查询缓存），与 ADR 0016 一致。新增权限位
  `vocabulary.view` / `vocabulary.create` / `vocabulary.manage` 进 `team-permission-matrix`；「改自己创建的」是
  `vocabulary.create` 叠加创建者判定。
- **额度**：团队词条条数计入团队 owner 套餐（`getLexiconQuota(team.ownerId)` 的 `customLexiconMaxTerms`），
  按 `teamId` 计数，按 `teamId` 加 advisory lock；owner 套餐不含自定义词汇时团队写入返回 `plan_gate_required`。
  个人词条仍按本人套餐、按本人计数，团队词条**不**计入创建者个人额度。
- **离队**：离队即失去对团队词汇的读写，团队词条留在团队、不跟人走，也不占离队者的个人额度，因此没有残留额度。
  账号被删除（DSAR）时，`userId` 外键级联会删掉该账号创建的团队词条（被擦除的是作者数据）；已冻结的快照不受影响。

### 4. 范围

本 ADR 覆盖单条增删改查、恢复、预览（dryRun）、词汇版本轮询（团队按团队维度取指纹）、词汇页团队切换。
批量导入、异步导入任务、快照列表 / 回滚、90 天降级归档仍只作用于个人词汇，团队维度后续按需再加
（这些入口在团队作用域下不提供，界面隐藏）。

## 后果

- 团队里的 Free 成员可以为团队策略新增词条，额度看团队 owner；个人词汇与个人策略不受影响。
- 所有按 `userId` 读个人词汇的查询必须同时限定 `ownerType='user'`，否则会把该用户创建的团队词条混进个人视图；
  实现以单一 owner 谓词收口。
- 编辑器在团队策略里多拉一份团队词条列表，多一路版本轮询（20s 一次，只在团队策略编辑时）。
- 团队快照没有 90 天归档与孤儿回收；团队删除后快照行保留（无外键），与个人快照的已删除策略引用同一处理方式。
- 部署顺序：迁移 0065 先于或后于 Worker 均可。先上 Worker 时团队写入因 CHECK 约束失败（返回 500，可重试），
- **回滚**：先把 Worker 回退到不含团队词汇的版本，再执行 `docs/runbooks/sql/0065-team-shared-vocabulary-rollback.sql`。脚本在一个事务里完成以下步骤：
  1. 把全部 `ownerType='team'` 行（含软删）整行导出到 `UserDomainTerm_team_backup_0065`，然后删除。旧 CHECK 不允许任何团队行，所以不能只做软删除。
  2. 恢复旧的活跃唯一索引和 `UserDomainTerm_owner_v1_check`。
  3. 从 `drizzle.__drizzle_migrations` 删除 0065 的记录，便于之后重新前滚。

  已冻结的团队快照不受影响，已审批版本照常执行。重新前滚时先跑 0065，再按脚本末尾的语句从备份表恢复团队词条。
  个人路径不受影响；先跑迁移时旧 Worker 只写个人行，新约束对其透明。

## 被否决的替代方案

- **额度取本人与团队 owner 的较大者**（#690 初版）：团队档泄漏到个人场景，离队收不回（审查 M3）。
- **维持现状**：团队 Free 成员只能用已有词汇，#672 不解决。
- **团队策略只读团队词汇**：上线即破坏现有团队策略的作者词汇（见 §2）。
- **冲突时报错、不裁决**：可编译性取决于保存顺序；且作者个人词条的修改会让整个团队的策略编译失败。
